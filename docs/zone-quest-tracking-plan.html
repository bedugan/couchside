Couchside: Quests · Revised scope

Track quests by zone.

Use the game's quest-log groups as the default. Scan the player's map for extra quests with work here. Accept that the game's markers do not describe every possible gathering location.

The zone-tracking option, read-only decision report, keep overrides and explicit watch API test are implemented. Watch APIs passed the in-game test, and Brian confirmed the initial zone filter works. Zone transitions, restoration, keep overrides and instance matching await broader playtesting.

The rule

Track the current zone or instance's group, plus accepted quests with a direct marker on the player's map. Untrack quests grouped elsewhere when they have no qualifying local marker. Keep the selected navigation quest.

What changes when you travel

  1. After entering a new zone or instance, wait briefly for location and quest data to settle.
  2. Read every accepted quest and its native quest-log group, including collapsed groups.
  3. Match the group to the current zone, parent outdoor maps, or native instance name.
  4. Scan the explicit player map for additional accepted quests with direct markers. Ignore quest-start and child-map markers. Browsing another zone's world map must not affect the scan.
  5. Apply the resulting watch list. Recompute local relevance for the new zone; do not accumulate quests from past zones.

Also scan on login or reload and when the quest log changes, so accepting or completing a quest takes effect without requiring travel. Coalesce events and avoid movement polling. Gate both decisions and background work with the option.

Examples

Missing location or groupLeave the watch state unchanged unless another usable source establishes relevance.

Keep the implementation small

One opt-in setting, quests.smartTracking, default off. The report is /cs quests tracking [questID]. The /cs quests tracking keep <questID> and auto <questID> commands provide explicit exceptions.

Keep selected navigation quests. Let manual changes stand until the location or quest progress changes, so incidental map and watch updates do not immediately fight the player's checkbox. Use explicit keeps for exceptions that should survive scans. Watch events do not identify whether the player or native auto-watch caused them.

Keep quest-specific state per character. Restore watch changes still owned by the addon when disabling it; preserve later manual choices. Respect watch capacity and native untracking restrictions. Log changes with ns.Debug.

The feature stays in Couchside_Quests. No quest database, per-objective geographic model, route planner or learning system is required. Update the README with each implemented command, option, file and confirmed game behavior.

Evidence already collected

  • Border Crossings retains its Silverpine marker after untracking.
  • With the Barrens map open, implicit map membership changes to false while the explicit player-map query still finds the Silverpine hand-in.
  • Sample for Helbrim is ready for hand-in and points to the Barrens.
  • The Book of Ur has group Shadowfang Keep, even with the heading collapsed and destination map zero.

These are sampled Forever results, not a guarantee for every quest. Some markers may represent routes or entrances. Non-geographic quest groups and multi-zone gathering can need a keep override.
