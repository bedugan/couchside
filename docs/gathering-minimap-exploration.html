The mechanism to investigate

Forever's Minimap:UpdateMouseoverAtPoint(x, y) and C_TooltipInfo.GetMinimapMouseover() read one sampled herb pin when soft-cursor mode was enabled and the point used physical screen coordinates. That establishes a working single-pin mechanism, not a complete gathering-node scan. The inspected Retail source declares the tooltip reader but does not declare the point-update method, so this route remains specific to the tested Forever client.

A list would require sampling points across the minimap, merging repeated hits into approximate pin positions, and reading the names. It must avoid interfering with the real cursor or Blizzard's tooltip. No direct live gathering-node list has been established.

Prove the data before building the display

  1. Compare ordinary mouse-hover tooltip data with an explicit point query on one isolated herb or ore pin.
  2. Establish coordinates and scaling. Check zoom, rotating minimap, edge pins and handheld UI scale.
  3. Try an addon-owned query frame if supported; check whether it sees the same live pins. Check native-tooltip interference if querying the real minimap.
  4. Check overlapping pins, players and tracking modes. A tooltip name alone must not be treated as a reliable herb/ore classification.
  5. Only if those checks pass, test a bounded scan for coverage, cost and stale results while moving. Missing a sample must not be reported as proof that a node is gone.

For a full scan, use minimap-relative direction first. Add yard distances only after verifying the position conversion. Keep any observed node distinct from a historical database location.

Where it belongs

A future Couchside_Gathering module would own gathering detection and display. It serves a separate purpose from quest tracking and controller action-page state. The first implementation step should be a diagnostic report, following the project's in-game verification rule.
