Couchside: Controller · Investigation · 7 October 2026

Return to page 1 after inactivity.

A small, independent Controller feature: enter page 2 or 3, use its actions, and return to page 1 after five seconds without another action attempt. Configure the delay from 3 to 10 seconds.

Feasibility is conditional.

Forever has a native controller page setter. We still need to establish whether an addon timer can use it during combat and whether the native action path exposes every relevant button press. Source inspection is not an in-game result.

Recommended behavior

  • Opt in with Automatically return to page 1, initially off. This works independently of the page-number display.
  • Return after defaults to 5 seconds, with whole-second choices from 3 through 10.
  • Entering page 2 or 3 starts a fresh countdown. Switching between them restarts it.
  • Each action attempt on the current controller page restarts the countdown, including a failed cast, an item or a macro. Brian confirmed that attempts should count. Input-path coverage still needs verification.
  • Movement, camera input, targeting and unrelated spells do not restart it.
  • Page 1, special pages and a hidden controller interface cancel the countdown. Returning to an eligible page starts fresh.
  • Do not change pages while the player is actively using the native page selector. Start a fresh countdown when selection ends.
  • Turning the feature off stops its timer and activity handling. Changing the delay starts a fresh countdown.

Example: select page 2 at 0 seconds, attempt a spell at 4 seconds, and make no further attempts. With the default delay, return to page 1 just after 9 seconds.

ControllerPageReport.luaExtend diagnostics to report native capability and observed input, without enabling automatic changes.
Couchside/Core.luaExpose a named value getter to modules and support validated numeric values in /cs option. Keep IsEnabled for feature gates.
Couchside/Settings.luaKeep existing checkboxes; add numeric option rendering using a native slider.
Controller TOC and READMEList the new file, settings, commands and confirmed behavior when implementation begins.

The base currently assumes every setting is boolean. Numeric support is a necessary shared change, while the return behavior belongs entirely in Controller. No dependency on the indicator's visibility or polling loop is needed.

Verify before building automation

  1. Add a retained report/watch command that prints the build, native page, controller visibility, page-setter availability, combat state and observed action attempts.
  2. Brian checks page 2 and 3 with ordinary spells, cooldown and range failures, items, macros, empty buttons, mouse clicks and controller input. Verify modifier-selected bars as well.
  3. Add an explicit one-shot return test, separate from the read-only report. Test outside combat first, then during combat. Inspect errors, actual action assignments and the next pressed action, rather than trusting the highlighted tile.
  4. If that succeeds, test a return initiated by a timer. A successful manual command alone does not establish that timer-driven changes work.
  5. Check page selection holds, special/override bars, interface transitions and a cast or channel longer than the delay. Decide whether long casts need countdown suspension from those results.
  6. Build the option and timer only after the probe establishes the supported behavior. Test 3, 5 and 10 seconds, repeated activity and disabling mid-countdown. Commit after Brian confirms it works.

If combat blocks the setter, an out-of-combat return is a narrower feature and should be described as such. Do not promise the requested combat behavior or try to bypass protection. The inspected Retail live source has no Blizzard_GamepadActionBars addon. Treat this as a Forever feature and leave Retail inactive when the native controller page unit is absent. Supporting a different Retail controller addon would be a separate integration.

Evidence

Forever's PageUnit.lua defines controller page getters, setters and page-change callbacks. The setter updates displayed actions, bar visibility, button state and the tracker. Use this path rather than the keyboard action-bar page API.

Blizzard's settings source defines numeric settings and native sliders with configurable bounds and steps.

Detailed API research records the input path, client differences and remaining runtime questions. Existing behavior and the Forever settings-panel workaround are recorded in the repository README. Proposed command names and options in this document are not implemented.
